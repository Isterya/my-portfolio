# Аудит портфолио перед версией 2.0

> Состояние кода: коммит `d5159ca` (ветка `main`). Номера строк в ссылках — для этого коммита. Цель
> v2.0: сайт должен продавать автора как сильного фронтенд-разработчика — работодателям и заказчикам
> на фрилансе. Поэтому всё ниже оценивается ещё и с вопросом «что увидит техлид, который откроет
> сайт, DevTools и GitHub».

## Кратко

1. **Сайт быстрый на десктопе и медленный на телефоне.** Lighthouse mobile: Performance 70, **LCP
   10,3 с**. Причина — 2,4 МБ PNG/JPG, которые грузятся все сразу, и водопад «main.js → lazy
   HomePage → картинки». Desktop при этом 98.
2. **Мультиязычность сломана для большинства реальных посетителей.** Браузер отдаёт `ru-RU` /
   `pl-PL` / `en-US`, а код ждёт `ru` / `pl` / `en`: переключатель показывает «English» при русском
   тексте, языковые CSS-правки не применяются (навбар «ломается»), дата на юридических страницах
   пустая, `<html lang>` всегда `en`.
3. **Прямые ссылки на `/privacy-policy` и `/user-terms` на проде отдают 404** (проверено на
   `*.vercel.app`): нет SPA-rewrite.
4. **Лиды могут теряться молча.** Сервер не проверяет ответ Telegram API, а фронт показывает
   пользователю сырые технические ошибки («Unexpected token 'T'…» при rate-limit).
5. **Превью ссылки в Telegram/LinkedIn без картинки.** OG-теги ставятся только через JS (краулеры
   соцсетей JS не выполняют), а `og:image` указывает на файл, которого нет в сборке.
6. **Доступность на уровне «почти»:** Lighthouse a11y 91, но реально — серый текст с контрастом
   2,6:1, ссылки-иконки без имени, нет `prefers-reduced-motion`, карусели не останавливаются для
   клавиатуры, точки слайдера — `div`.
7. **Инструменты качества врут.** `npm run lint` после сборки падает с 1595 ошибками (линтится
   `dist/`), `npm run build` переписывает закоммиченный файл, тестов и CI нет, README обещает
   «optimized Core Web Vitals» и «Nodemailer failover», которых нет.

Хорошее, что стоит сохранить: строгий TypeScript без ошибок, разнесённые по секциям компоненты и
стили, данные вынесены в `src/data`, переводы в JSON, роуты с `lazy()`, husky + lint-staged,
отсутствие горизонтального скролла на ширинах 320–1920 px.

## 1. Архитектура

### ARCH-1. Чистый CSR без пререндеринга · P1 (план на v2.1)

- **Проблема.** `index.html` содержит пустой `<div id="root">`. Контент, мета-теги и даже первая
  отрисовка появляются только после загрузки и выполнения 126 КБ (br) JS. Три языка живут на одном
  URL, язык выбирается в браузере.
- **Почему важно.** FCP на телефоне ≥ 2 с при любом качестве картинок; краулеры соцсетей видят
  пустую страницу; Google индексирует только английскую версию; RU/PL-контент для поиска не
  существует.
- **Как исправить.** Пререндер (SSG) на этапе сборки: `vite build --ssr` + скрипт, который рендерит
  роуты через `renderToString` и `StaticRouter`, клиент — `hydrateRoot`. Язык — в URL (`/`, `/ru/`,
  `/pl/`) + `hreflang` + `<html lang>` на сервере. Предусловия: убрать JS-зависимую разметку
  (ARCH-2) и обращения к `window` на этапе рендера.
- **Почему не сейчас.** Это смена схемы URL и стратегии SEO, плюс без ARCH-2 гарантированы hydration
  mismatch на мобильных. В этой ветке сделаны независимые шаги, которые к этому ведут.

### ARCH-2. Адаптивность через JS, а не через CSS · P2

- **Проблема.** `useIsTouchDevice()` решает, _какую разметку_ рендерить: NavBar (бургер или
  десктоп-меню), Experience (две разные раскладки), Footer (две копии одинаковой разметки), Price (6
  или 18 карточек), SkillsSlider. Брейкпоинты продублированы в JS и SCSS.
- **Почему важно.** Дублирование кода, лишние ре-рендеры на resize, риск рассинхронизации JS- и
  CSS-брейкпоинтов, невозможность SSR без hydration mismatch.
- **Как исправить.** Где разметка одинаковая — один вариант + медиа-запросы (Footer). Где разная —
  общий подкомпонент без дублирования JSX (Experience). Оставшийся JS-брейкпоинт — один источник
  истины.
- **Где.** `src/components/footer/Footer.tsx:68-134`,
  `src/sections/experience/Experience.tsx:53-230`.

### ARCH-3. Определение языка не учитывает региональные коды · P0

- **Проблема.** i18next настроен без `supportedLngs` (`src/i18n/index.ts:12-22`), поэтому
  `i18n.language` = `ru-RU` / `pl-PL` / `en-US`. Код сравнивает его с `ru` / `pl` / `en`:
  `LanguageSwitcher.tsx:38-41`, `useLastUpdated.ts:6`, CSS `html[data-lang='ru']` в
  `styles/style.scss`.
- **Почему важно.** Проверено в браузере с `ru-RU`: текст русский, переключатель «English», языковые
  CSS-правки не применяются (активный пункт навбара вылезает за скругление), дата обновления
  политики пустая. Это видит почти каждый RU/PL-посетитель.
- **Как исправить.** `supportedLngs: ['en','ru','pl']`, `load: 'languageOnly'`,
  `nonExplicitSupportedLngs: true`; везде использовать `i18n.resolvedLanguage`; один модуль с типом
  `AppLanguage` и списком языков.

### ARCH-4. Главная страница грузится через `lazy()` · P1

- **Проблема.** `src/routes/index.tsx:6` — `HomePage` лениво импортируется, хотя это входная точка
  95 % визитов.
- **Почему важно.** Лишний сетевой круг: HomePage-чанк и CSS запрашиваются только после выполнения
  главного JS (на трассе: старт на 1118 мс против 27 мс у main.js). Плюс на первом заходе мигает
  полноэкранный белый `Loader`.
- **Как исправить.** Импортировать HomePage статически, ленивыми оставить политику, условия и 404.

### ARCH-5. Дата «Last updated» генерируется из git при каждой сборке · P0

- **Проблема.** `npm run build` запускает `generate:dates` (`src/scripts/generateLastUpdated.ts`),
  который берёт дату последнего коммита _TSX-файла страницы_ и перезаписывает закоммиченный
  `src/data/lastUpdated.ts` (в другом стиле кавычек — рабочее дерево «грязное» после каждой сборки).
- **Почему важно.** Vercel клонирует репозиторий неглубоко, поэтому `git log -1 -- file` возвращает
  граничный коммит — дата на юр. страницах случайная (в этом окружении получилось «8 мая 2025»
  вместо «26 апреля 2025»). Кроме того, юридический текст живёт в JSON-локалях, а отслеживается TSX
  — правка формулировок дату не меняет, а рефакторинг разметки — меняет.
- **Как исправить.** Хранить дату редакции явно (ISO-строка в `src/data/legal.ts`), форматировать
  через `Intl.DateTimeFormat` по активному языку. Генератор и `tsx`-скрипт убрать из сборки.

### ARCH-6. Конфигурация деплоя · P0 / P2

- **Проблема.** Нет `vercel.json` → прямой заход на `/privacy-policy` даёт 404 (проверено на
  `my-portfolio-git-main-isteryas-projects.vercel.app`). Хешированные ассеты отдаются без
  `immutable`. В `server/render.yaml` секция `routes` — это настройка статического сайта, для
  Node-сервиса она бессмысленна.
- **Почему важно.** Ссылки на политику из письма, поиска или чата ведут на 404 (P0); повторные
  визиты перепроверяют каждый файл (P2).
- **Как исправить.** `vercel.json` с `rewrites` на `/index.html` и
  `Cache-Control: public, max-age=31536000, immutable` для `/assets/*`; убрать `routes` из
  `render.yaml`.

### ARCH-7. Контент и конфигурация размазаны по коду · P2

- **Проблема.** Адрес почты захардкожен в 5 местах, Telegram — в 2, адрес сайта — в 4 (то
  `https://isterya.dev`, то `http://www.isterya.dev`), ссылки на сертификаты — внутри JSX
  `Experience.tsx`, дата рождения — внутри `About.tsx:30`, «8+ проектов» — в JSX, «over three years»
  — текстом в локали, хотя число лет считается кодом.
- **Почему важно.** Любая правка контента — поиск по проекту; данные расходятся (в 2027 году герой
  покажет «4 года», а текст — «более трёх лет»).
- **Как исправить.** `src/config/site.ts` (URL, контакты, соцсети), данные секций — в `src/data`,
  числа — через интерполяцию i18next.

### ARCH-8. Инструменты качества · P1 / P2

- **Проблема.**
  - В `eslint.config.ts` нет `ignores` → после `npm run build` линтер проверяет `dist/` и падает с
    1595 ошибками (P1 — ломает рабочий процесс «собрал → проверил»).
  - Флаг `--ext` в скрипте `lint` — наследие eslintrc; поле `"eslint": {"configFile": …}` в
    `package.json` ничего не делает; `tsconfig.eslint.json` нигде не используется и без алиасов не
    компилируется.
  - 10 неиспользуемых devDependencies (`eslint-plugin-import`, `eslint-plugin-prettier`,
    `eslint-plugin-react-refresh`, `globals`, `ts-node`, `stylelint-prettier` и др.) и
    неиспользуемая runtime-зависимость `resend` (серверный SDK во фронтенде).
  - `prettier --check .` не проходит на 5 файлах; lint-staged запускает только prettier и stylelint,
    ESLint в pre-commit не участвует.
  - Тестов нет, CI нет.
- **Почему важно.** Работодатель, открывший репозиторий, видит «enterprise tooling» в README и
  красный `npm run lint`.
- **Как исправить.** `ignores: ['dist', 'server/dist', 'node_modules']`, убрать мёртвые настройки и
  зависимости, добавить ESLint в lint-staged, Vitest для чистой логики, GitHub Actions (build +
  lint + test) — последнее требует прав на workflow в репозитории.

## 2. Код

### CODE-1. `useSlider`: пагинация «съезжает» и автопрокрутка не знает о видимости · P1

- **Проблема.** `nextSlide` = `(prev + itemsPerSlide) % dataLength`
  (`src/hooks/useSlider.ts:39-45`). Если количество не делится на размер страницы (15 навыков по 2
  на планшете), после первого круга индексы становятся нечётными: показываются пары `[1,2]`,
  `[3,4]`, активная точка не соответствует слайду. При смене брейкпоинта индекс не выравнивается.
  Автопрокрутка тикает, когда секция за экраном или вкладка скрыта, и не останавливается при фокусе
  с клавиатуры.
- **Почему важно.** Видимый баг на планшетах; лишняя работа; нарушение WCAG 2.2.2 (движущийся
  контент без паузы).
- **Как исправить.** Считать в страницах (`page = floor(index / perPage)`), чистые функции
  пагинации + тесты; пауза по `IntersectionObserver`, `visibilitychange`, `focusin`/`focusout`.

### CODE-2. `useCarousel` (бегущая строка цен) · P1

- **Проблема.**
  - Шов цикла: сброс на `scrollWidth / 3`, а реальный период — `6 × (ширина + gap)`. Разница — треть
    зазора (≈11 px на десктопе): **каждый цикл строка дёргается**.
  - Вечный `requestAnimationFrame`, даже когда секция за экраном.
  - Хук ищет карточки глобально: `document.querySelectorAll('.price-card')`
    (`src/hooks/useCarousel.ts:53`) и совмещает две несвязанные задачи (marquee + reveal-анимация).
  - Не учитывает `prefers-reduced-motion`, не останавливается при фокусе.
- **Как исправить.** Период = смещение первой карточки второй копии
  (`children[n].offsetLeft − children[0].offsetLeft`); IntersectionObserver на трек; reveal — через
  ref контейнера; reduced motion → статичный ряд.

### CODE-3. Контактная форма и `sendEmail` · P0

- **Проблема.** `src/services/sendEmail.ts:8` вызывает `res.json()` до проверки статуса. Rate-limit
  сервера отвечает текстом → пользователь видит
  `Unexpected token 'T', "Too many r"... is not valid JSON`. Если `VITE_API_URL` не задан, запрос
  уходит на `undefined/send-email`. Сообщения сервера («Error sending to: Telegram») показываются
  как есть, по-английски, на любом языке (`Contact.tsx:41-42`, `catch (err: any)`). Нет таймаута, а
  бесплатный инстанс Render после сна просыпается 30–60 с — всё это время на кнопке «Sending…».
- **Почему важно.** Это единственная точка конверсии сайта.
- **Как исправить.** Типизированная ошибка (`network` / `rate-limit` / `validation` / `server` /
  `timeout`) → локализованное сообщение; `AbortController` с таймаутом; «прогрев» сервера, когда
  секция контактов попадает в зону видимости.

### CODE-4. Дублирование в `Experience.tsx` · P2 (+ контентный баг P1)

- **Проблема.** Конфигурация четырёх ссылок на сертификаты скопирована дважды (строки 78-114 и
  185-221), карточка опыта отрисована тремя почти одинаковыми кусками JSX. **Ссылки «JavaScript» и
  «React» ведут на один и тот же сертификат** (`UC-3ca32cc1…`, строки 83 и 99).
- **Как исправить.** Данные ссылок — в `src/data/experienceData.ts`, карточка — подкомпонент.
  Правильный URL React-сертификата должен дать автор.

### CODE-5. `Footer` — две копии одной разметки · P2

- **Проблема.** `Footer.tsx:68-134`: ветки для `isSmallDevice` отличаются только обёрткой
  `.footer-columns`. Якоря навигации вычисляются из ключей перевода
  (`link.replace('footer.navigation.', '')`).
- **Как исправить.** Одна разметка, обёртка с `display: contents` на десктопе; явные
  `{ id, labelKey }`.

### CODE-6. `uuid` для статических данных · P2

- **Проблема.** `skillsData`, `portfolioData`, `priceData` генерируют `uuidv4()` при загрузке
  модуля: id меняются при каждой загрузке, зависимость лишняя (и в установленной версии есть
  advisory GHSA-w5hq-g745-h8pq).
- **Как исправить.** Стабильные строковые id (`'react'`, `'uber'`), удалить `uuid`.

### CODE-7. Захардкоженные английские строки в UI · P2

- **Проблема.** `aria-label` («Toggle menu», «Previous slide», «Go to slide N», «Hero section»),
  `alt` («A mascot character», «Icon for price card»), SEO-заголовки и описания — только
  по-английски. В герое `aria-label="I’m Bohdan, Web Developer"` **перекрывает** переведённый
  заголовок: RU/PL-скринридер читает английский текст (`Hero.tsx:52`).
- **Как исправить.** Ключи `a11y.*` в локалях; убрать `aria-label`, дублирующие видимый текст.

### CODE-8. `NavBar` · P2

- **Проблема.** Обработчик `scroll` без `passive`, на каждое событие читает `offsetTop` шести секций
  и вызывает `setState`; секции собираются один раз при монтировании; блокировка прокрутки пишет
  inline-стиль в `<html>` и не восстанавливает его при размонтировании; параметр `_` в
  `SECTIONS.map((section, _) =>`.
- **Как исправить.** Scroll-spy на `IntersectionObserver`, `{ passive: true }`, хук `useScrollLock`
  с восстановлением исходного значения.

### CODE-9. `LanguageSwitcher` · P2

- **Проблема.** Состояние хранится в виде отображаемого имени («Русский»), соответствие имя ↔ код
  продублировано тернарниками; «клик снаружи» ищет `.lang-switcher` по классу (сломается при двух
  экземплярах); нет поддержки клавиатуры (Escape, стрелки).
- **Как исправить.** Список `{ code, label }`, ref вместо селектора, `aria-expanded`, Escape.

### CODE-10. Мелочи · P3

- Имя файла `PorfolioCard.tsx` (опечатка), `getYearOfExperience.ts` экспортирует
  `getYearsOfExperience`, тип `tocSection` с маленькой буквы.
- Смешение `@/…` и относительных импортов (`../../data/footerData`).
- `Loader` описывает `exit`-анимацию, но не обёрнут в `AnimatePresence` — она никогда не
  выполняется; ради одного спиннера подключён `react-spinners`.
- `SEO` рендерит `<meta property="og:image">` без `content`, если картинки нет (404).
- `getYearsOfExperience` считает разницу календарных лет: 1 января число лет вырастет, хотя
  годовщина в ноябре.

### CODE-11. Стили: нет дизайн-токенов, ручная адаптивность · P2

- **Проблема.** `#ff7f00` встречается в SCSS 10+ раз, серые (`#344054`, `#98a2b3`, `#171717`) — в
  каждом файле; в `_variables.scss` всего три переменные. Почти у каждого свойства 5–6 ручных
  переопределений по брейкпоинтам — отсюда 66 КБ CSS на одну страницу. `transition: all` в 13 местах
  (анимируются и `height`, и `padding`).
- **Почему важно.** Редизайн (см. `docs/design.md`) превратится в правку сотен значений.
- **Как исправить.** Токены цвета/радиусов/длительностей в CSS custom properties; fluid-типографика
  через `clamp()` (это уже изменение дизайна — в рамках выбранного направления).

## 3. Производительность

### PERF-1. Картинки · P1 (главная причина LCP 10 с)

- **Проблема.** Все растровые изображения — PNG/JPG без оптимизации, все грузятся сразу (нет
  `loading="lazy"`, нет `width`/`height`):
  - `main-bg.jpg` 496 КБ (используется дважды, на мобильном — LCP-элемент);
  - `hero-character.png` 444 КБ, `abstract-figure-3.png` 428 КБ, `about-character.png` 379 КБ,
    `abstract-figure-1.png` 135 КБ;
  - шесть скриншотов проектов 167–295 КБ каждый — при отображаемом размере 633×371.
  - Скриншоты проектов — `background-image` в inline-стиле, их нельзя отложить или отдать в
    нескольких размерах.
- **Почему важно.** Lighthouse оценивает экономию в 1,76 МБ. На медленном 4G LCP-картинка делит
  канал с ещё 1,9 МБ картинок «ниже сгиба».
- **Как исправить.** Конвертация в WebP с подбором качества (визуально без потерь), отложенная
  загрузка всего ниже первого экрана, `width`/`height` против CLS, `fetchpriority="high"` для героя,
  скриншоты проектов — `<img loading="lazy">` с `object-fit: cover`.

### PERF-2. JavaScript · P1 / P2

- **Проблема.** Главный чанк 149 КБ gzip. В нём все три локали (≈48 КБ, нужна одна), полный
  framer-motion (≈113 КБ, используется `motion.div` + `whileInView`), react-helmet-async с тремя
  зависимостями. Плюс водопад из ARCH-4.
- **Как исправить.** HomePage — в основной чанк (P1); неактивные локали — динамическим импортом
  (P2); framer-motion → `LazyMotion` + `m` с асинхронной загрузкой фич, простые появления — на CSS
  (P2, вместе с работой по анимациям из `docs/design.md`).

### PERF-3. Шрифты · P2

- **Проблема.** Два блокирующих рендер CSS-файла с `fonts.googleapis.com` без `preconnect`; Poppins
  запрошен в 9 начертаниях, используются 6 (300–800); Inter — во всём вариативном диапазоне.
  Lighthouse: блокирующие запросы ≈450 мс на mobile.
- **Почему важно.** Скорость + GDPR: загрузка Google Fonts с CDN Google передаёт IP посетителя в
  Google (решение LG München, 2022), а политика конфиденциальности этого не упоминает.
- **Как исправить.** Минимум — `preconnect` и только используемые начертания, один запрос. Правильно
  — self-hosting woff2 с `font-display: swap` и `preload` основного начертания (решение про файлы
  шрифтов — вместе с выбором дизайн-направления).

### PERF-4. Работа в рантайме · P2

- **Проблема.** Вечный rAF бегущей строки (CODE-2), интервалы двух слайдеров тикают вне экрана
  (CODE-1), 9 бесконечных CSS-анимаций крупных PNG-слоёв, `backdrop-filter: blur()` на 18 карточках
  цен и 3 карточках навыков, `transition: all` на навбаре (анимируются `height` и `padding` —
  перерасчёт layout каждый кадр).
- **Как исправить.** Останавливать анимации вне экрана; анимировать только `transform`/`opacity`;
  ограничить `backdrop-filter` (детали — в `docs/design.md`).

### PERF-5. Кэширование и мелочи · P2 / P3

- Нет `immutable`-кэша для `/assets/*` (см. ARCH-6).
- `favicon.ico` 15 КБ; нет SVG-иконки, `apple-touch-icon`, манифеста (P3).

### A11Y-2. Контраст · P1 (требует дизайн-решения)

- **Проблема.**
  - Основной серый текст `#98a2b3` на белом — **2,58:1**, на `#f2f4f7` — 2,34:1 (нужно 4,5:1): опыт,

### A11Y-3. Ссылки и кнопки без доступного имени · P1

- **Проблема.** Круглая стрелка «открыть проект» (`PorfolioCard.tsx:30-35`) — ссылка без текста.
  «Hire me» с `aria-label="Scroll to contact section"` — имя не содержит видимого текста (WCAG

- **Как исправить.** `aria-label` с названием проекта и пометкой «откроется в новой вкладке»,
  декоративным картинкам — `alt=""`, убрать конфликтующий `aria-label`.

### A11Y-4. Форма · P1

- **Проблема.** У email-поля нет `<label>` (только placeholder), у поля и чекбокса **нет видимого
  фокуса** (`outline: none`, чекбокс скрыт `opacity: 0`, у `.checkmark` нет стиля фокуса); ошибка не
  связана с полем (`aria-invalid`, `aria-describedby`).
- **Как исправить.** Визуально скрытый `<label>`, `:focus-visible` для поля и `.checkmark`, связь
  ошибки с полем.

### A11Y-5. Клавиатура · P1

- **Проблема.**
  - Точки портфолио-слайдера — `div` с `onClick`: с клавиатуры недоступны вообще. Точки слайдера
    навыков — `div role="button"` только с Enter (без Space).
  - Горизонтально прокручиваемый ряд цен на мобильном не получает фокус (axe:
    scrollable-region-focusable).
  - Мобильное меню: у бургера нет `aria-expanded`/`aria-controls` и `outline: none`; после Escape
    фокус теряется на `<body>`.
  - Выпадающий список языков не закрывается по Escape, нет `aria-expanded`.
- **Как исправить.** Нативные `<button>`, `aria-current`, `tabIndex={0}` + `role="region"` с
  подписью для прокручиваемого ряда, возврат фокуса на бургер, обработка Escape.

### A11Y-6. Движение · P1

- **Проблема.** Нет поддержки `prefers-reduced-motion`: при включённой настройке продолжают работать

  возможности паузы с клавиатуры (WCAG 2.2.2).
- **Как исправить.** Глобальное правило для CSS, `<MotionConfig reducedMotion="user">`, пауза
  каруселей при фокусе внутри и при reduced motion.

### A11Y-7. Семантика · P2

- **Проблема.**
  - Цифры «8+» и «3+ Years» размечены как `h3`; в карточке проекта два одинаковых `h3`; заголовки
    колонок футера — `h4` сразу после `h2`.

## 5. SEO и шаринг

### SEO-1. Соцсети не видят OG-теги и картинку · P1

- **Проблема.** OG/Twitter-теги добавляются через react-helmet в рантайме — Telegram, LinkedIn,
  Facebook, X их не видят. `og:image` указывает на
  `https://isterya.dev/assets/img/home-preview.jpg`, но превью-картинки лежат в `src/assets/img`,
  нигде не импортируются и в сборку не попадают.
- **Почему важно.** Портфолио распространяется ссылкой в мессенджерах и LinkedIn — карточка без
  картинки выглядит небрежно.
- **Как исправить.** Картинки — в `public/og/`; базовые OG/Twitter-теги — статически в `index.html`
  (с `data-rh`, чтобы Helmet их подменял, а не дублировал); абсолютные URL от одного `SITE_URL`.

### SEO-2. Дубль `meta description`, канонический домен · P1

- **Проблема.** В `index.html` своё короткое описание, Helmet добавляет второе — на странице два
  `<meta name="description">`. Канонический URL и `og:url` — `https://isterya.dev`, в футере —
  `http://www.isterya.dev`. Доступность домена `isterya.dev` из окружения аудита проверить не
  удалось — **если домен не обслуживает сайт, canonical указывает на мёртвый адрес**.
- **Как исправить.** Один источник `SITE_URL` (с переопределением через `VITE_SITE_URL`), одна
  версия домена (https, без www) во всех ссылках; проверить, что домен привязан к проекту Vercel.

### SEO-3. Нет `robots.txt` и `sitemap.xml` · P1

- **Проблема.** Файлов нет; после добавления SPA-rewrite `/robots.txt` начнёт отдавать HTML.
- **Как исправить.** `public/robots.txt` со ссылкой на `public/sitemap.xml`.

### SEO-4. Soft 404 · P1

- **Проблема.** Несуществующие URL отдают 200 (после rewrite) и страницу с `canonical` на главную,
  без `noindex`.
- **Как исправить.** `<meta name="robots" content="noindex">` на 404, без canonical.

### SEO-5. Мультиязычное SEO · P2 (зависит от ARCH-1)

- **Проблема.** Один URL на три языка, нет `hreflang`, заголовки и описания страниц только
  английские.
- **Как исправить.** Локализованные SEO-строки сразу; URL на язык + `hreflang` — вместе с ARCH-1.

### SEO-6. Структурированные данные · P3

- JSON-LD `Person` (имя, должность, `sameAs` на GitHub/LinkedIn) и `ProfessionalService` (услуги,
  цены «от») — расширенные сниппеты и понятность для ассистентов поиска.

### Безопасность и надёжность

#### SEC-1. Ответ Telegram API не проверяется — лиды теряются молча · P0

- **Проблема.** `server/src/utils/sendToTelegram.ts:15-19`: `fetch` не бросает исключение на
  4xx/5xx. Отозванный токен или неверный `CHAT_ID` → сервер отвечает «успех», клиент получает письмо
  «скоро свяжусь», а владелец не узнаёт о заявке.
- **Как исправить.** Проверять `response.ok` и `ok` в JSON-ответе Telegram.

#### SEC-2. Семантика «всё или ничего» · P1

- **Проблема.** Заявка считается неудачной, если не ушло _подтверждение клиенту_ (например, адрес с
  опечаткой), даже когда Telegram-уведомление доставлено. Пользователь видит ошибку и отправляет
  повторно — дубли. README при этом описывает «email failover», которого в коде нет.
- **Как исправить.** Критичный канал — уведомление владельцу; подтверждение клиенту — best effort с
  логированием.

#### SEC-3. Почтовый «отражатель» · P1

- **Проблема.** `POST /send-email` отправляет письмо на любой адрес от имени автора; CORS открыт для
  всех (`cors()`), лимит — 5 запросов в минуту на IP, без капчи и honeypot.
- **Почему важно.** Скрипт с ротацией IP превращает сервер в рассыльщик писем на чужие адреса —
  жалобы на спам, блокировка аккаунта Brevo и репутации домена.
- **Как исправить.** Honeypot-поле, CORS по списку `ALLOWED_ORIGINS`, ограничение повторов на один
  адрес; при реальных атаках — Cloudflare Turnstile.

#### SEC-4. Уязвимые и лишние зависимости · P1

- **Проблема.** Фронтенд: `react-router` 7.6.0 — пакет advisories (часть касается только SSR, но
  open redirect через `<Link>` актуален и для SPA); `uuid` < 11.1.1. Сервер: `express` 4.18 тянет
  уязвимые `path-to-regexp`, `body-parser`, `qs`, `send`, `cookie`; `nodemailer` и `node-fetch`
  установлены, но не используются (Brevo вызывается через глобальный `fetch`).
- **Как исправить.** `npm audit fix` в пределах semver, удалить неиспользуемое, `express.json()`
  вместо `body-parser`.

#### SEC-5. Прочее · P2

- Ответ 429 и необработанные ошибки — текст, а не JSON (ломает клиента, см. CODE-3).
- Нет `GET /health` — невозможно «разбудить» Render заранее.
- Политика конфиденциальности утверждает, что сайт использует cookies и Google Analytics, — в коде
  аналитики нет; при этом не упомянуты Google Fonts, Brevo, Telegram и Render как обработчики
  данных. Политика пишет «не для детей до 13», условия — «только 18+».

### Что нужно сделать автору

1. **Render:** задать `ALLOWED_ORIGINS` (например,
   `https://isterya.dev,https://www.isterya.dev,https://my-portfolio-git-main-isteryas-projects.vercel.app`)
   — до этого API принимает запросы с любых сайтов и пишет предупреждение в лог.
2. **Домен:** убедиться, что `isterya.dev` открывает сайт. Если основной адрес другой — поменять
   `SITE_URL` в `src/config/site.ts` и статические теги в `index.html`.
3. **Контент:** ссылка на React-сертификат, «8+ проектов» и «5 звёзд», превью для соцсетей
   (`public/og/home.jpg` показывает «2 Years»), политика конфиденциальности (аналитики нет; Google
   Fonts, Brevo, Telegram и Render как обработчики; возраст 13 против 18 в условиях).
4. **Дизайн:** выбрать направление из `docs/design.md` — от него зависят A11Y-2, RESP-1, RESP-2,
   CODE-11, PERF-3 и переработка анимаций.
